# 손님 화면 명세 — 카페

> 화면마다 스탠드형(세로) · 갤럭시탭형(가로) 디자인이 있고, **동작은 같습니다.** 레이아웃만 다릅니다.
> 공통 동작은 core `docs/04`(결제) · `docs/05`(출력) · `docs/06`(쿠폰)을 따릅니다.

## 1. 시작 — 매장 / 포장 선택

- 디자인: [`00-start`](../screenshots/00-start.png) (스탠드) · [`sw-00-start`](../screenshots/sw-00-start.png) (갤럭시탭)

**구성**

- 가게 이름 · 로고 · 대표 사진(세팅 2단계에서 올린 것)
- "어디서 드시나요?" + `매장` / `포장` 큰 버튼
- "선택하신 내용은 주문서에 함께 인쇄돼요"
- (갤럭시탭형) 영업시간 표시

**예외 · 규칙**

- `한국어 · English`, `큰 글씨` 버튼은 MVP에서 숨김

**다음**: 매장 / 포장 선택 → 주문 세션 시작 → 메뉴

## 2. 메뉴 선택

- 디자인: [`Main`](../screenshots/Main.png) (스탠드) · [`sw-01-menu`](../screenshots/sw-01-menu.png) (갤럭시탭)

**구성**

- 상단 매장 / 포장 탭 — 시작 화면 선택과 같은 쪽 선택 상태, 눌러서 바꿀 수 있음 (주문서 인쇄 값도 바뀜)
- 분류 칩: 추천 · 에스프레소 · 콜드브루 · 블렌디드 · 티 · 푸드
- 메뉴 카드: 사진 자리 · 이름 · 가격 · 배지 · 담은 수량
- 품절 메뉴는 흐리게 + `품절`, 누를 수 없음
- 하단 장바구니 요약: 개수 · 합계 · `주문 확인 ›`

**예외 · 규칙**

- 장바구니 비어 있으면 `주문 확인` 비활성

**다음**: 메뉴 누름 → (업종 itemConfigurator) → 장바구니

## 3. 음료 옵션

- 디자인: [`02-option`](../screenshots/02-option.png) (스탠드) · [`sw-02-option`](../screenshots/sw-02-option.png) (갤럭시탭)

**구성**

- 메뉴 사진 · 이름 · 설명
- 온도 · 사이즈 · 샷 · 시럽 · 얼음 · 컵 선택
- 수량 − +
- `5,800원 담기` (옵션 반영 금액)

**예외 · 규칙**

- 필수 옵션 미선택 시 담기 비활성
- ICE ONLY 메뉴의 HOT 선택 불가

## 4. 주문 확인 (장바구니)

- 디자인: [`03-cart`](../screenshots/03-cart.png) (스탠드) · [`sw-03-cart`](../screenshots/sw-03-cart.png) (갤럭시탭)

**구성**

- 매장 / 포장 배지, 총 개수, `전체 삭제`
- 항목: 이름 · 옵션 요약 · 수량 − + · 삭제 · 금액
- 상품 금액 · 결제 금액
- `더 담기` / `결제하기 ›`

**예외 · 규칙**

- 수량 0 → 삭제 확인
- 업종 cartRules 위반 시 안내 후 결제 불가

**다음**: 결제하기 → 결제 방법

## 5. 결제 방법 선택

- 디자인: [`04-pay-method`](../screenshots/04-pay-method.png) (스탠드) · [`sw-04-pay`](../screenshots/sw-04-pay.png) (갤럭시탭)

**구성**

- 주문 요약 + 매장 / 포장 배지 + 결제 금액
- `전체결제` / `더치페이` **좌우 버튼** (같은 크기)
- 점선 `쿠폰 사용 — 시리얼 번호 입력 · 바코드 스캔` 진입 바 (`specs/coupon.md`)
- 안내 박스
- `주문 내역으로` / `직원 호출`

**예외 · 규칙**

- 카드 단말 미연결 → 결제 버튼 막고 직원 호출 안내
- 인터넷 끊김 → 결제 불가 안내

**다음**: 전체결제 → 카드 승인 / 더치페이 → 분할 방식

## 6. 스탬프 적립 (전화번호)

- 디자인: [`05-stamp`](../screenshots/05-stamp.png) (스탠드) · [`sw-05-stamp`](../screenshots/sw-05-stamp.png) (갤럭시탭)

**구성**

- 결제 방식 표시(전체결제)
- 휴대폰 번호 숫자 키패드
- 현재 스탬프 → 적립 후 미리보기 (`7 → 10 / 10`)
- 10개 달성 안내
- 개인정보 수집 · 이용 동의
- `적립 안 함` / `적립하고 16,600원 결제`

**예외 · 규칙**

- 번호 자리수 오류
- 동의 안 하면 적립 불가 (결제는 가능)

**다음**: 전체결제: 번호 입력 후 카드 승인 / 더치페이: 결제자마다 이 단계 반복 (`06-dutch`의 `번호 입력`)

## 7. 더치페이

- 디자인: [`06-dutch`](../screenshots/06-dutch.png) (스탠드) · [`sw-06-dutch`](../screenshots/sw-06-dutch.png) (갤럭시탭)

**구성**

- 방식 탭: N등분 · 메뉴별 · 금액 입력
- 전체 · 결제 완료 · 남은 금액
- 결제자 행: 완료 / 진행 중 / 대기
- 방식별 입력 (인원 수, 메뉴 선택, 금액)
- `N번째 0,000원 결제하기`
- `직원 호출`

**예외 · 규칙**

- 결제 건 거절 → 그 건만 재시도
- 손님 중간 취소 불가 (직원 PIN)
- 진행 중 무입력 초기화 없음

**다음**: 남은 금액 0원 → 주문 확정 → 출력 → 완료

## 8. 주문 완료

- 디자인: [`07-done`](../screenshots/07-done.png) (스탠드) · [`sw-07-done`](../screenshots/sw-07-done.png) (갤럭시탭)

**구성**

- "주문이 접수되었어요", 매장 / 포장 · 주문번호 크게 (`C-042`)
- 업종 안내 문구 (`docs/01`)
- 30초 뒤 처음 화면 안내
- `영수증 출력` / `처음으로`

**예외 · 규칙**

- 출력 실패여도 완료 화면은 정상 표시 (대기열 처리)

**다음**: 처음으로 → 시작 화면, 세션 초기화

## 수용 시나리오

아래가 모두 되면 카페 손님 흐름 완료입니다. (core 공통 시나리오 `docs/10` 2장 + 아래)

- [ ] 카페 라떼 ICE 그란데 → 5,200 + 600 = 5,800원
- [ ] 콜드브루 → 온도 선택 없이 ICE
- [ ] 음료 3잔 전체결제 + 번호 입력 → 스탬프 +3
- [ ] 스탬프 7개 회원이 3잔 주문 → 10개 달성 → 무료 쿠폰 발급 → 스탬프 0개
- [ ] 더치페이 메뉴별 3명 → 각자 번호로 각자 잔 수만큼 적립
- [ ] 크로플만 주문 → 스탬프 적립 대상 아님 안내
- [ ] `적립 안 함` → 적립 없이 결제 완료
- [ ] 쿠폰 `신메뉴 출시 1,000원 할인` 16,600원 → 15,600원
